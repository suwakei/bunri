# 画面のことば（用語集）

bunri の画面・使い方の画面・初回の案内に出す文は、ここの決まりに合わせる。
同じものを別の名前で呼ぶと、利用者は別のものだと受け取る。新しい文を書くときも、文を直すときも、
まずここを見る。決まりを変えるときは、この文書と画面の文を一緒に直す。

## 用語

| 使うことば | 指すもの | 使わないことば |
|---|---|---|
| **原曲** | 取り込んだ曲の音声そのもの | 元音源、ソース、楽曲ファイル（ファイル選択の欄の説明を除く） |
| **お手本** | 原曲を採譜して得たノート。差分チェックで、利用者の打ち込みと比べる相手。MIDI ファイルのノートも「お手本として読み込む」でお手本にできる（パートの一覧に出る） | 答え、答え合わせ、正解、模範解答 |
| **パート** | 原曲を楽器ごとに分けた 1 つぶん（ボーカル、ドラム、ベース…） | ステム、レイヤー、完全分解、Decompose |
| **パート分離** / **パートに分ける** | 原曲をパートに分ける処理 | ステム分離、音源分離、完全分解、深層分離 |
| **採譜** | 音声からノートを読み取ること | 書き起こし、ピッチ検出、トランスクライブ |
| **ノート** | ピアノロールに置く 1 つの音 | 音（数えるとき・指すとき）、音符、ノーツ |
| **カルテ** | 原曲の解析結果（キー・コード進行・構成・ミックス）をまとめたもの | レポート、解析結果（見出しとして） |
| **再現ガイド** | カルテを「こう作れば再現できる」という手順に言い換えたもの | AI の解説、アドバイス |
| **差分チェック** | お手本と打ち込みを比べて、違いを一覧にする機能 | 答え合わせ、採点 |
| **打ち込み** | 利用者がピアノロールに置いたノート | 回答、入力結果 |
| **トラック** | タイムラインの 1 行。クリップとノートを持つ | チャンネル |
| **クリップ** | トラックに置いた音声のひとかたまり | リージョン、素材 |
| **プロジェクト** | 1 曲の作業をまとめたもの。トラック・ノート・お手本・音声・カルテ・学ぶ流れの状態・学習の記録を、1 つの `.bunri` ファイルに保存する | セッション、ドキュメント、ファイル（保存したものを指すとき。「.bunri のファイル」と言うのは可） |
| **最近使ったプロジェクト** | 最近開いた・保存したプロジェクトの一覧（空の状態の案内と、ヘッダの ▾ のメニュー）。一覧から外しても、ファイルは消えない。無くなったファイルは「見つかりません」と出す | 履歴、最近のファイル |
| **以前の形式** | 前の版の bunri が保存したプロジェクト（`projects/*.json`。音声を持たない）。開く一覧で札を付けて示す。保存すると `.bunri` になる（元のファイルは消さない） | 旧形式、レガシー |
| **保存していない変更** | 最後に保存した（開いた）ときから変わったところ。題名とヘッダのプロジェクト名の後ろの「●」で示す。開く・新しいプロジェクト・窓を閉じる前に「保存 / 保存しない / キャンセル」を尋ねる | 未保存、ダーティ |
| **音声の無いクリップ** | 以前の形式から開いたときの、位置と長さだけが残ったクリップ。「音声を読み込み直す」で手元のファイルを選び直す | 欠損、リンク切れ |
| **学習の記録** | 差分チェック・練習画面で比べるたびに残る、一致率と違いの件数の履歴。差分の段と練習画面の見出しに「一致 72% ▲前回より +8%」の形で出す（前回は同じ区間の 1 つ前の記録）。プロジェクトに入る | 履歴、ログ、成績 |
| **一致率** | 比べた範囲のお手本のノートのうち、打ち込みと合っていたノートの割合（%）。差分チェックの「〜% が合っています」と同じ値。前回との差は「+8%」「−3%」「±0%」 | 正答率、スコア、点数 |
| **データの整理** | ファイルのタブの、アプリのデータの置き場の使用量と、一時ファイルを消す操作。保存したプロジェクトは消さない | キャッシュの削除、クリーンアップ |
| **原曲のトラック** | 取り込んだ曲の音声を置いたトラック。名前は「原曲」 | 元音源トラック、オリジナル |
| **パートのトラック** | パートに分けて作った、パートの音声とお手本を持つトラック（「ベース」など） | ステムトラック |
| **練習のトラック** | 「このパートを練習する」で作る、利用者が打ち込むトラック。名前は「（パート名）の練習」 | 回答トラック、解答欄 |
| **進み具合** | ヘッダの下の 5 つの段階（① 曲を取り込む ② カルテを見る ③ パートに分ける ④ 打ち込む ⑤ 差分で直す）。段階の名前は案内（ウェルカムガイド）と同じにする | ステップ、チュートリアル、進捗 |
| **再生位置** | いま鳴っている場所。タイムラインとピアノロールに金色の線で出る | プレイヘッド、再生ヘッド |
| **処理を担当する部分** | 解析・分離・書き出しを受け持つ部分（デスクトップ版の Python sidecar、開発用の API サーバ）。止まったときの知らせで使う | バックエンド、サーバ、sidecar（開発用のブラウザ起動の案内で「API サーバ」と言うのを除く） |
| **中止** / **キャンセル中…** | 時間のかかる処理をやめるボタンは「中止」。頼んでから止まるまでの間は「キャンセル中…」（区切りのよいところでしか止まらない処理が在るため）。止まったあとは「〇〇を中止しました」 | 停止（再生の停止と紛れる）、取り消し |
| **段階** | 時間のかかる処理の、いまの区切り（「段階 2/5」）。進み具合のカードで使う | ステージ、フェーズ |
| **学ぶ / 音作り / ファイル** | 左パネルの 3 つのタブ。「学ぶ」の中は「曲とパート」「カルテ」「ガイド」「差分」の段 | — |
| **元に戻す / やり直す** | 最後の操作を取り消す / 取り消した操作をもう一度する。ヘッダの ↶ / ↷、⌘Z / ⌘⇧Z | アンドゥ、リドゥ、取り消し（ボタンの名前として） |
| **音量** | トラックの大きさ（dB）。トラックの見出しのつまみ。読み上げと数字は「−6.0 dB」（マイナスは「−」） | ゲイン、ボリューム |
| **パン** | トラックの左右の位置。数字は「左 30」「中央」「右 30」 | 定位、L30 / R30 |
| **メニュー** | トラックの「…」、クリップの右クリックで出る小さな一覧（「名前を変更」「複製」「削除」など） | コンテキストメニュー |
| **選ぶ / 選択** | ピアノロールで、操作するノートを決めること（囲む・Shift+クリック・⌘A）。選んだノートは白い縁取り | セレクト |
| **コピー / 切り取り / 貼り付け / 複製** | 選んだノートを写す / 写して消す / 再生位置に置く / すぐ後ろに置く | ペースト、デュプリケート |
| **表示の大きさ** | ピアノロールの横・縦の拡大と縮小（「横に広げる」「縦に縮める」） | ズーム（画面の文で） |
| **練習画面** | 「このパートを練習する」で開く、ピアノロールを大きく出して「入力 → 比べる → 直す」を回す画面。タイムラインと左パネルは隠れる | 練習モード、フォーカスモード |
| **アレンジ** / **アレンジに戻る** | 練習画面に対する、ふだんの画面（タイムライン・左パネル・ピアノロール） | 通常モード、編集画面 |
| **区間ループ** / **区間** | 練習画面で、決めた小節の範囲を繰り返し鳴らすこと / その範囲（「1〜2 小節」） | ループ範囲、A-B リピート、リージョン |
| **速度** | 練習画面で、音の高さを変えずに遅くする割合（50〜100%）。「75%」 | テンポ（テンポは BPM のこと）、再生速度、スロー |
| **聴く** | 練習画面で、鳴らすものを選ぶ: パート（パートの音声）/ 自分（自分のノート）/ 両方 | モニター、ミックス |
| **強さ** | ノートを弾いた強さ（ベロシティ。1〜127）。MIDI 鍵盤で弾いたノート、MIDI ファイルから読み込んだノート、採譜したお手本が持つ。強いほど大きく鳴り、ピアノロールでは濃く見える。マウスで置いたノートは強さを持たず、96 として鳴る | ベロシティ（画面の文で。括弧で添えるのは可）、音量（トラックの音量と紛れる） |
| **録音前にカウント** | MIDI 入力のリアルタイム録音で、再生の前に 1 小節ぶんのクリックを鳴らすこと。カウントの間は、曲は進まず、弾いても録らない | カウントイン、プリロール |
| **遅れの補正** | リアルタイム録音で、弾いた位置を前へ戻す量（ミリ秒）。聞こえた音に合わせて弾くと、音が耳に届くまでの遅れのぶんだけ後ろに置かれるので、そのぶんを戻す。決めなければ、音の出力の遅れから決まる（「おまかせに戻す」） | レイテンシ補正、オフセット |
| **比べる** / **一致** | 練習画面でお手本と打ち込みを比べる操作 / 比べた区間のお手本のうち、高さと位置が合っていたノートの割合（「一致 72%」） | 採点、スコア、正答率 |

「お手本」は自動採譜の結果で、原曲と違っていることがある。だから「正解」とは呼ばない
（[coach-diff-design.md](coach-diff-design.md) の「限界」）。グリッドの確認のように、お手本と関係の無い
場面でも「正解です」とは書かず、「合っています」と書く。

「ノート」の例外: 耳に聞こえる音そのものを言うときは「音」でよい（「音が鳴る」「音の高さ」「音の始まり」）。
個数を数えるとき・ピアノロール上のものを指すときは「ノート」（「5 ノート」「ノートを置く」「余分なノート」）。
差分チェックの指摘の種類は、抜け / 高さの違い / オクターブ違い / 余分なノート / 位置のずれ / 長さの違い。

「お手本をノートとして取り込む」: パートのお手本を、そのパートのトラックの打ち込みに写す操作の名前。
写すと差分チェックが 100% から始まるので、押した後にその場で確かめてから写す。「答えを取り込む」とは言わない。
写した後も「元に戻す」で、それまでの打ち込みに戻せる。

消す操作（トラック・クリップ）は、確かめの窓を出さずにすぐ消し、「〜を削除しました」の知らせに「元に戻す」を付ける。
元に戻したときは、ステータスバーに「元に戻しました（操作の名前）」と出す。操作の名前は「ノートを追加」「「Track 1」を削除」
のように、何をしたかが分かる短い名前にする（↶ のボタンの説明にも出る）。

「パート」の例外: ツールの画面の「パート分離」の説明に 1 回だけ、技術的な名前（Demucs による音源分離、
モデル名）を添えてよい。モデルの選択肢には、モデルの名前（`htdemucs_6s` など）をそのまま出す。

## 動詞

| 使うことば | 意味 | 使わないことば |
|---|---|---|
| **取り込む** | 原曲を、解析のためにアプリへ入れる | インポート、読み込む（原曲に対して）、アップロード |
| **開く** | 保存したプロジェクトを開く（⌘O）。開くと、それまでの元に戻すの履歴は消える（新しい文書になる） | 読み込む（プロジェクトに対して）、ロード |
| **読み込む** | トラックに置く音声ファイルや、MIDI ファイルのノートを入れる。以前の形式のプロジェクトを開いたときの知らせも「読み込みました」 | 読込、ロード、インポート |
| **書き出す** | WAV や MIDI のファイルとして外へ出す | 書出、エクスポート、ダウンロード（DAW の画面で） |
| **保存する** | プロジェクトを残す（⌘S）。初めての保存は、デスクトップ版では保存先を選ぶ（既定は「書類」の bunri フォルダ） | セーブ |
| **別名で保存する** | いまのプロジェクトを、別の名前・場所の .bunri として保存する（⇧⌘S）。以後はその新しいファイルが開いているプロジェクトになる | 名前を付けて保存（メニューの名前として） |
| **追加する** | トラックやクリップやノートを足す | 挿入、インサート |
| **置く** | ノートをピアノロールに入れる | 配置する（ボタンの名前に残っているものを除く）、入力する |
| **練習する** | お手本を重ねて、自分でそのパートを打ち込む（「このパートを練習する」） | 回答する、挑戦する |
| **自由に作る** | 曲を取り込まずに、空のトラックから作る | フリーモード |

ヘッダのボタンは、動詞まで書く: 「保存」「開く」「WAV 書き出し」「MIDI 書き出し」。▾ のメニューは「新しいプロジェクト」「別名で保存…」「最近使ったプロジェクト…」。
確かめの窓のボタンは「保存」「保存しない」「キャンセル」の 3 つ（この順。「保存しない」は消す操作の色）。

ツールの画面は、処理した結果のファイルを受け取る場所なので、リンクの名前は「ダウンロード」のままにする。

## 書き方

- **省略の記号は「…」。** 「...」（ピリオド 3 つ）は使わない。処理中の文は「〜しています…」
- **「！」は使わない。** 終わったことは、落ち着いた文で伝える（「パートに分けました」）
- **内部の名前を出さない。** API のパス、変数名、エフェクトの識別子（`pitch_shift`）、状態コード（`HTTP 500`）、
  生の JSON は、画面に出さない。エフェクトは日本語の名前で言う（「ピッチシフト」を適用しました）
- **失敗の文は「何が起きたか」+「次にどうすればよいか」。** 「エラー: 」で始めない。
  失敗の文はステータスバーで色が変わり（`--error`）、読み上げの対象になる（`role="alert"`）ので、
  頭に「エラー」と書かなくても失敗だと分かる。文の組み立ては `lib/api.ts` の `errorDetail` /
  `describeError` / `statusMessage` に集めてある
- **開発者向けの文は、デスクトップアプリでは出さない。** バックエンドの再起動、環境変数
  （`ANTHROPIC_API_KEY`）、「このブラウザでは…Chrome / Edge」は、開発用のブラウザ起動のときだけ出す
  （`lib/api.ts` の `isDesktop()` で分ける）
- **半角の英数字と日本語のあいだは、半角の空白を 1 つ空ける。** 「WAV ファイル」「MIDI 書き出し」「4 小節」。
  単位が後ろに付く短い数（「8ビート」「4つ打ち」のような固有の呼び名）は、そのままでよい
- **シンセとエフェクトのつまみの名前は日本語。** 定着しているカタカナ語（アタック、リバーブ）はそのまま使い、
  意味はマウスを載せたときの説明（ツールチップ）で補う

### マウスを載せたときの説明（ツールチップ）

ボタン・入力欄・タブ・つまみには、マウスを載せると、そばに短い説明が出る（`components/Tooltip.tsx`）。
初めて触る人が「押すと何が起きるか」を、押す前に分かるようにするためのもの。
付け方は、要素に `{...tip('説明')}`（`lib/tooltip.ts`）と書くだけ。ブラウザ標準の `title` は使わない
（出るまで 1 秒ほど待たされ、出る位置も選べない）。

書き方:

- **押すと何が起きるかを書く。** ボタンの名前を言い換えるだけの文にしない。
  「保存」なら「テンポ・トラック・ノートを保存します。音声そのものは保存されません」のように、結果と、知らないと困ることを書く
- **1〜2 文で終える。** 長くなるなら、パネルの説明文（`panel-desc`）か使い方の画面に書く
- **初めての人が知らない言葉を、説明なしで使わない。** 「ソロ」「パン」のような言葉は、何が聞こえるかで言い換える
  （「再生したとき、このトラックだけが聞こえるようにします（ソロ）」）
- **飾らない。** 「便利です」「簡単に」「ぜひ」「〜しましょう」は書かない。「！」も使わない（上の決まりと同じ）
- **状態で変わるボタンは、いま押したときのことを書く。** 再生中の ▶ は「一時停止します」、ミュート中の M は
  「ミュート中です。押すと、また鳴るようになります」
- **キー操作は `key` に分けて書く**（`tip('…', { key: 'Space' })`）。文の後ろにキーの形で出る

出す場所（`data-tip-side` を置き場所の祖先に書く。入らなければ反対側、横、の順に逃がし、画面の外には出さない）:

| 置き場所 | 向き | 理由 |
|---|---|---|
| ヘッダ・進み具合・タブの段 | 下 | 上は画面の外。タブは横に出すと隣のタブに重なる |
| 左パネル | 右（パネルの外） | パネルの中の、次に触る欄を隠さない |
| トラックの見出し | 右（見出しの外） | M・S・パンが並んでいるので、隣のボタンを隠さない |
| ピアノロールの上の帯・シークバー・ステータスバー | 上 | 下のノートや画面の端を避ける |

「〜の外」は `data-tip-box` を書いた枠の外側にそろえる指定。押したら消え、そのまま同じ場所に居るあいだは出し直さない。
ツールチップはマウスの操作を受けないので、下の要素はそのまま押せる。

## 色

色の名前を文に書くときは、実際に出ている色と合わせる。色の値は `web-ui/src/styles/global.css` の
`:root` に名前（トークン）で置いてあり、コードには値を直接書かない
（canvas に描くときは `lib/theme.ts` の `cssVar` で読む）。

| トークン | 色 | 文での呼び方 | 使いどころ |
|---|---|---|---|
| `--accent` | 金色 | 金色 | 選んでいるもの、主なボタン、ノート、小節の頭の線 |
| `--secondary` | 青緑 | 青緑 | ディグリー、構成の区間、トラック単体の再生 |
| `--ok` | 緑 | 緑 | うまくいった・確かである（確信度「確実」）。練習画面の「合っている」ノートの縁 |
| `--warn` | 黄色 | 黄色 | 注意（解析結果に無い用語、音域の外のノート）。練習画面の「高さが違う」（斜線）と「位置か長さがずれている」（点線の縁） |
| `--error` | 薄い赤 | 赤 | 失敗の知らせ、確信度「自信なし」。練習画面の「お手本にないノート」（× 付き）と「お手本の抜け」（赤い破線のお手本） |
| `--info` | 水色 | 水色 | 補足の知らせ |
| `--ghost` | 水色（破線の縁と薄い塗り） | 水色 | お手本のノート（薄く重ねて見せる） |
| `--selection` | 白に近い色 | 白い縁取り | 選んでいるノート・クリップの縁取り |
| `--danger` | 赤 | 赤 | 消す・止める操作（ミュート中、録音中） |

メニューの「削除」「トラックを削除」は、消す操作として `--error`（薄い赤）の文字にする。

選んでいるノートは、色を変えずに白い縁取りで示す。赤は「違っているノート」のために空けてある。

文字の色は 3 段階: `--text`（本文）、`--text-mid`（ラベル・説明）、`--text-dim`（補足）。
どれも、パネルの背景の上で 4.5:1 以上のコントラストがある。文字の大きさの下限は、
鍵盤の音名のような詰まった表示で 10px、ラベルで 11px、パネルの本文で 12px。

練習画面の差分の色は、色だけに頼らない（模様・縁・記号を変え、凡例と読み上げの名前を付ける）。
読み上げの名前は「F2: 高さが違う。1 小節 2 拍目: F2 → お手本は E2」の形（印の呼び名 + 差分チェックの指摘の文）。
