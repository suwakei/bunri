# アシスタントの設計（アプリの中のチャット）

画面の右側のチャットで頼むと、アシスタント（Claude）が bunri を操作する。行った操作と、その結果は、
チャットの中に **操作ログ** として並ぶ。2026-11-18 に利用者の依頼で足した。

「アシスタント」は、アプリの中のこの機能のこと（Claude Code のことではない）。考え方は別のアプリ
pairbrush のアシスタントに倣っている（「倣ったこと・変えたこと」の節）。

## 何ができるか

- チャットで「4 小節のベースを置いて」「Track 2 をミュートして 3 小節目から再生して」のように頼む
- アシスタントは、ツール（下の表）で bunri を操作する。読む操作（プロジェクトの様子、ノート、カルテ、再現ガイド、
  お手本との差分）と、変える操作（再生、テンポ、トラック、ノート、練習画面とその設定、MIDI 入力、クリップ（動かす・縮める・分ける・フェード）、エフェクト、
  パート分離、書き出し、保存）が在る
- 「パート分離はどこ？」のように場所を聞くと、そのタブを開いて、部品を短いあいだ光らせる（押すのは利用者）
- 何も無いときは、いまの状況に合った頼み方の例を 3 つ出す（決まった規則で選ぶ。Claude は呼ばない）
- 応答は、少しずつ出る（下の「応答を少しずつ返す」）
- 会話は、プロジェクトを保存すると一緒に入り、開き直すと戻る（下の「会話の保存と、長くなったときのまとめ」）
- 「新しい会話」を押しても、それまでの会話は消えずに「履歴」に残る。ヘッダの「履歴」から開き直して続きを頼める・消せる
- 操作 1 つごとに、チャットに 1 行出る（「ノートを 8 個置きました（Track 1、1〜2 小節）」）。
  行を開くと、その操作のあいだにアプリの中で起きたこと（[動きの記録](ui-testing.md) の行）が出る
- 1 回の依頼で変えたことは、まとめて 1 回の「元に戻す」で戻せる（チャットの「元に戻す」、ヘッダの ↶、⌘Z）
- 途中で「中止」できる。そこまでに行った操作は残り、「元に戻す」で戻せる

## 原則との関係（2026-11-18 の利用者の決定）

bunri の原則は「DSP が事実を出し、LLM は言語化だけをする。LLM は音符を 1 つも出力しない」。
これは、原曲を教材にする 3 層（カルテ・再現ガイド・差分コーチ）の原則として、そのまま残る。

アシスタントは別の役目で、**利用者に頼まれた操作を代わりに行う**。ノートを置く・変える操作も持つ
（利用者が決めた）。以前の音楽アシスタント（`music_assistant.py`。2026-11-12 に外した）との違い:

- 自分から曲を作って渡すのではなく、利用者がチャットで頼んだ操作を、ツールで 1 つずつ行う
- 行ったことは、すべて操作ログに出て、1 回で元に戻せる
- 指示文で、学ぶ流れを壊さないようにしている（頼まれていないのに、お手本をそのまま打ち込みへ写さない）

## 全体の形

```
チャット (画面)                         処理を担当する部分 (Python)              Claude
  │  POST /api/assistant/step  ───────────▶  指示文 + ツールの台帳を付けて  ─────▶  messages
  │   {messages, turn_id, step}                 1 回だけ呼ぶ (状態は持たない)
  │  ◀───────────  {content, stop_reason, usage, today}  ◀──────────────────────────
  │
  ├─ stop_reason が tool_use なら、画面がツールを実行する (アプリの状態は画面に在る)
  │   結果を tool_result にして messages に足し、step を 1 つ進めて、もう一度呼ぶ
  └─ end_turn なら、文を出して終わり
```

- **ツールを実行するのは画面**。トラックもノートも再生も、画面（WebView）の中に在るため
- **繰り返しを回すのも画面**。Python 側は 1 回の呼び出しごとに完結し、会話の状態を持たない
  （pairbrush と同じ。サーバが回すと、画面との双方向の通信が要る）
- **Claude を呼ぶのは Python 側**。API キー・使用量の記録・1 日の上限・偽の Claude でのテストは、
  再現ガイドと差分コーチの仕組み（`llm_settings`、`guide_usage`）にそのまま載せる
- 呼び出しは公式の `anthropic` SDK の Messages API。Claude Managed Agents（Anthropic 側がループと実行環境を持つ）は
  使わない。ツールが全部このアプリの中で動くので実行環境が要らず、会話を Anthropic 側に残さず、
  費用の記録と上限を手元の仕組みで一元に数えられるため

## API

`POST /api/assistant/step`（JSON）

| 項目 | 中身 |
|---|---|
| `messages` | Claude の Messages API の `messages` そのまま（下の「会話の持ち方」）。1〜200 件 |
| `turn_id` | この依頼の識別子（英数字とハイフン、64 文字まで）。使用量の記録で、同じ依頼の呼び出しを束ねる |
| `step` | この依頼の何回目の呼び出しか（0 から）。`MAX_STEPS`（12）以上は 400 |

応答（200）:

| 項目 | 中身 |
|---|---|
| `content` | Claude の応答の `content`（ブロックの配列）。**変えずに** assistant のメッセージとして `messages` に足す |
| `stop_reason` | `end_turn` / `tool_use` / `max_tokens` |
| `model` | 実際に答えたモデル |
| `usage` | 4 つの計器と思考のトークン数（再現ガイドと同じ形） |
| `cost_usd` | この 1 回の概算の費用（単価の表に無いモデルなら null） |
| `today` | 今日の使用量（`guide_usage.today()`） |

失敗は、再現ガイドと同じ形（`{"detail": {"message", "code"}}`）と同じ番号。
`no_key` / `auth`（401）、`daily_limit` / `rate_limit`（429）、`invalid`（400）、`too_long`（413）、
`refused`、`network`、`api`。

### 応答を少しずつ返す（ストリーミング）

本文に `"stream": true` が在るときだけ、応答を少しずつ返す（画面は、これを付けて呼ぶ）。無ければ、上の JSON 1 つ。
確かめ・1 日の上限・使用量の記録は、どちらも同じ（`assistant.step` と `assistant.stream_step` が、同じ部品を使う）。

成功は 200、`Content-Type: application/x-ndjson`、`Cache-Control: no-store`、`X-Accel-Buffering: no`。
1 行に JSON 1 つ + 改行:

| 行 | 中身 |
|---|---|
| `{"type":"text","text":"<差分>"}` | 見える文（text ブロック）の差分 |
| `{"type":"tool","name":"<ツール名>"}` | Claude が `tool_use` のブロックを書き始めた（1 ブロックにつき 1 回。引数はまだ無い） |
| `{"type":"done","content":[…],"stop_reason":…,"model":…,"usage":{…},"cost_usd":…,"today":{…}}` | 最後の行。上の JSON の応答と同じ項目 |
| `{"type":"error","detail":{"message":…,"code":…},"today":{…}}` | 流し始めた後の失敗（最後の行）。`detail` は HTTP エラーの `detail` と同じ形 |

決めたこと:

- **失敗の返し方は、いつ分かったかで分かれる**。呼び出しの前に分かる失敗（引数・会話の形、1 日の上限）と、
  Claude への接続を開いた時点で分かる失敗（キーが無い・正しくない、利用制限、接続できない）は、`stream` が
  在っても上と同じ HTTP エラー。そのために、Claude へのストリームを開いてから応答を返し始める。
  流し始めた後の失敗（モデルが断った、想定していない終わり方、途中で途切れた、応答を読み取れなかった）は、
  200 のまま `error` の行になる。画面は、`done` も `error` も来ないまま本文が終わったら、失敗として扱う
- **会話に足すのは `done` の `content`**。`text` の行をつないだものではない（思考のブロックが入らず、
  次の呼び出しが通らない）。思考のブロックの差分は流さず、`done` の `content` に署名ごと入れる。
  ツールを実行するのも、`done` が来てから（`tool` の行は「書き始めた」の知らせで、引数を持たない）
- **使用量の記録は、成功・失敗・中止のどれでも、1 回の呼び出しにつき 1 行**。画面が途中で切ったとき（中止）は、
  Claude へのストリームを閉じて、`error: "cancelled"` で残す。入力のぶんの使用量は残るが、出力のぶんは
  最後まで届かないと確定しないので、実際より少ない。切ったことに気づくのは、次の行を出すところ
  （文もツールの始まりも出ない間は、Claude の応答を読み続ける）
- **リクエストは、まとめて返すときと同じ**（`build_request`。SDK が `stream: true` を足すだけ）。ツール定義に
  `eager_input_streaming` は付けない（引数の差分は画面に出さないので得が無く、付けると引数の JSON を
  サーバ側で検証しなくなる）

### 会話の持ち方

- Claude に送る会話は、画面が持つ（プロジェクトに入れるのは、画面に並んだ文と操作ログの行だけ。下の
  「会話の保存と、長くなったときのまとめ」。「新しい会話」で空にする）
- 形は Messages API のまま: 利用者の文は `{"role":"user","content":[{"type":"text","text":…}]}`、
  アシスタントの応答は `{"role":"assistant","content": <応答の content そのまま>}`、
  ツールの結果は `{"role":"user","content":[{"type":"tool_result","tool_use_id":…,"content":…,"is_error"?:true}, …]}`
- **前のメッセージを書き換えない・間引かない**（足すだけ）。応答には思考のブロックが入っていて、
  変えると次の呼び出しが通らなくなる（モデルの側の検査）。プロンプトキャッシュも、頭からの一致で効く。
  縮めるのは依頼の境目だけで、そのときは会話を丸ごと「これまでの記録」1 つに置き換える（途中だけを抜かない）
- 1 つの応答に `tool_use` が複数在れば、**全部の結果を 1 つの user のメッセージ**にまとめて返す

## ツール

台帳は `backend/assistant_tools.json`（Claude に渡す定義の正本）。画面側は同じ名前の実行する関数を
`web-ui/src/lib/assistant-tools.ts` に持つ。名前の過不足は、画面側の単体テストが台帳を読んで止める
（pairbrush の教訓: 手で写した 2 つの一覧は必ずずれる）。

| 名前 | 読む / 変える | 行うこと |
|---|---|---|
| `get_project` | 読む | テンポ・拍子・1 小節のステップ数・曲の長さ・トラックの一覧（クリップも）・開いているトラック・再生中か・メトロノーム・カルテの有無・練習画面とその設定・**選んでいるノート**・学ぶ流れの進み具合・プロジェクトの名前と保存していない変更・動いている処理 |
| `get_notes` | 読む | トラックのノート（`source: "reference"` でお手本）。小節で絞れる。選んでいるノートには `selected` が付く。400 個まで |
| `get_chart` | 読む | カルテ（キー・コード進行・構成） |
| `play` / `stop` / `seek` | 変える | 再生・停止・小節へ移動 |
| `set_tempo` / `set_time_signature` | 変える | BPM（20〜300）、拍子（3 / 4 / 6） |
| `add_track` / `rename_track` / `delete_track` / `select_track` | 変える | トラックの追加・名前・削除・ピアノロールで開く |
| `set_track_mix` | 変える | ミュート・ソロ・音量（−60〜+6 dB）・パン |
| `add_notes` / `remove_notes` / `replace_notes` | 変える | ノートを足す・範囲で消す・範囲で置き換える（1 つずつ書き直すとき） |
| `transpose_notes` / `shift_notes` / `quantize_notes` / `repeat_notes` / `set_velocity` | 変える | ノートの変形: 移調・前後へずらす（小数のステップも可）・位置（と長さ）をそろえる（32 分・16 分・8 分・4 分・2 分・全音符・8 分と 16 分の三連）・くり返して置く・強さ（一定に・足す・なだらかに） |
| `open_practice` / `close_practice` | 変える | 練習画面 |
| `set_practice` | 変える | 練習画面の設定: 区間ループ（小節）・速度（50〜100%）・聴く・お手本を見せるか |
| `set_metronome` | 変える | メトロノーム |
| `midi_input` | 変える | MIDI 入力をつなぐ・止める、録り方 |
| `check_diff` | 読む | お手本と打ち込みの差分（一致の %、種類ごとの数、重い小節、指摘の一覧）。差分は信号処理の側が出す事実で、Claude は呼ばない |
| `get_guide` | 読む | 保存済みの再現ガイド（新しくは作らない） |
| `show_in_app` | 読む | 画面の場所を示す（タブを開き、部品を光らせ、どこに在るかの文を返す） |
| `get_job` / `cancel_job` | 読む / 変える | 動いている、時間のかかる処理（パート分離・カルテの作成）の進み具合・中止 |
| `separate_parts` | 変える | パート分離と採譜を始める（終わるのを待たない） |
| `export_wav` / `export_midi` / `save_project` | 変える | 書き出し・保存（ヘッダのボタンと同じ処理） |
| `move_clip` / `delete_clip` / `duplicate_clip` | 変える | 音声のクリップを動かす・消す・複製する |
| `trim_clip` / `split_clip` / `fade_clip` | 変える | 音声のクリップを縮める（伸ばす）・2 つに分ける・フェードを付ける。音声は書き換えない |
| `apply_effect` | 変える | 音声のクリップにエフェクトをかける（EQ・コンプレッサー・リバーブ・ディレイ・ノーマライズ・ピッチシフト・タイムストレッチ） |

実行する関数は、種類ごとにファイルを分けてある: `assistant-tools.ts`（読む・再生・トラック・ノートを置く / 消す / 置き換える・
練習画面の開閉・MIDI 入力）、`assistant-tools-notes.ts`（ノートの変形）、`assistant-tools-learn.ts`（差分・ガイド・練習の設定・
メトロノーム・場所を示す）、`assistant-tools-app.ts`（処理・書き出し・保存・クリップ・エフェクト）。引数の確かめなどの部品と、
画面の入口の形（`ToolEnv`）は `assistant-tool-kit.ts`。

決めたこと:

- **位置はステップ（16 分音符）**、0 が 1 小節目の頭。小節は 1 から。ノートの高さは `"C4"` の形
  （フラットで来たら、画面側でシャープに直す。ピアノロールはシャープしか描けない）
- **ステップと長さは、小数を受ける**（`ASSISTANT_VERSION` 4 から。単位は 16 分音符のまま: 0.5 = 32 分音符、4/3 = 8 分の三連、
  2/3 = 16 分の三連）。ノートの `step` / `length`、範囲の `start_step` / `end_step`、`shift_notes` の `steps`、`repeat_notes` の
  `to_step` は、台帳で `"type": "number"`。画面側は `stepValue`（`assistant-tool-kit.ts`）で読み、1/60 ステップの倍数にそろえる
  （`lib/grid.ts` の `normStep`。Claude が `1.3333` と書いても、ちょうど 4/3 になる）。範囲に入るか・同じ位置かは、
  刻みの数（1/60 ステップの整数）で比べる。Claude に返すときは、小数 4 桁まで（`stepOut`。`1.3333`）。長さの下限は 0.25。
  数える項目（小節・回数・半音・強さ）は、整数のまま
- **`quantize_notes` の間隔**は、`grid_steps`（数）で受ける: 0.5（32 分）・0.6667（16 分の三連）・1（16 分）・1.3333（8 分の三連）・
  2・4・8・16。三連の値は整数で書けないので、台帳では決まった値の並び（enum）にせず、説明に書いて、画面側で近い値に読む
  （0.01 ステップまでの違いは同じ値。`quantizeGrid`）。台帳の説明に在る値と、画面が受ける値の一致は、単体テストが止める。
  以前は「位置はもう 16 分音符の単位なので、16 分の間隔は無い」としていたが、小数の位置が在るので、16 分にそろえる意味が在る
- **刻みとスウィングは、ツールにしていない**（`get_project` にも載せていない）。アシスタントは、置きたい位置を小数のステップで
  直接渡せる（シャッフルなら、裏の 8 分を三連の 3 つ目 = 拍の頭 + 2.6667 に置く、と指示文に書いてある）
- **どのトラックのノートも id で変えられる**（開いていなくてもよい）。そのための入口を、ピアノロールの側に足す
- **`strict`（ツールの引数を文法で縛る機能）は使わない**。引数は画面側が自分で確かめ、だめなら
  `is_error` の結果に理由を書いて返す（Claude は直して呼び直せる）。トラックが在るか・範囲の中かは
  どのみち画面でしか確かめられないのと、pairbrush が同じ仕組みの文法の大きさの上限で何度も 400 を
  受けていて、本物の Claude で確かめずに入れられないため
- **確かめの窓は出さない**。bunri の決まり（消す操作は確かめずに、元に戻せるようにする）に合わせる
- **一様な変更は、専用のツールで行う**（移調・ずらす・そろえる・くり返す・強さ）。`replace_notes` で数百のノートを
  書き直させると、遅く、高く、写し間違える。専用のツールは、範囲と量だけを受けて、決まった計算で変える。
  対象の選び方は共通（範囲 `[start_step, end_step)`・高さ・`selected_only`）。変えたノートは、開いているトラックなら
  選んで光らせる（どこが変わったかを見せる）
- **「ここ」は、選んでいるノートか、練習画面の区間**。`get_project` の `selection`（ピアノロールで選んでいるノートの
  数と範囲）と `practice.loop` で読ませ、`selected_only` で、選んでいるノートだけを対象にできる
- **差分は、事実だけを返す**（`check_diff`）。「DSP が事実を出し、LLM は言語化だけ」の原則のまま、アシスタントは
  返ってきた事実を言葉にする。言語化の API（`/api/coach/explain`）は呼ばない（Claude をもう 1 回呼ぶことになる）。
  練習画面と同じ範囲で比べるときは、画面の「比べる」を通す（ノートに色が付き、学習の記録に 1 件残る）。
  違う範囲のときは、計算だけして、画面は変えない。**お手本がドラムのパートなら、ドラムの比べ方**（種類ごとの叩く位置だけ。
  [coach-diff-design.md](coach-diff-design.md)「ドラムの差分」）で比べる。比べ方は、差分チェックの段・練習画面と同じ関数
  （`lib/drums.ts` の `diffModeOf`）で決める。結果には、比べ方の説明（`comparison`。高さは音の高さではなく種類、長さは比べない、
  種類違いは抜け + 余分）と、ノートごとの種類の名前（`drum`）を添える（事実の読み方を、台帳ではなく結果の側で伝える。
  台帳と指示文は変えていない）。以前の分け方のドラム（お手本を持たない）は、分け直すと比べられる、と返す
- **パート分離を始めるとき、ドラムを種類ごとに分けるのは、追加のモデルが手元に在るときだけ**（`separate_parts`。
  約 160 MB のダウンロードは、利用者が画面で選んだときだけ。ツールの引数は足していない）
- **練習の速度は、練習画面の設定で変える**（`set_practice`。音の高さを変えずに遅くする）。テンポ（`set_tempo`）は
  プロジェクトの値で、練習のために変えさせない（指示文と、ツールの説明に書いてある）
- **時間のかかる処理は、始めるだけで返す**（`separate_parts`）。数分かかるので、1 回の依頼の中では待たない。
  進み具合は `get_job` と、左のパネルの「曲とパート」。すでに分けてあるときは、`replace_existing: true` を
  求める（パートと練習のトラックが入れ替わるので、利用者に確かめさせる。確かめの窓の代わり）
- **曲の取り込みは、ツールにしない**。ファイルを選ぶ窓は利用者の操作でしか開かないので、場所を示して
  （`show_in_app` の `import_song`）、押してもらう
- **書き出し・保存・エフェクトは、画面のボタンと同じ処理を呼ぶ**（`lib/export-actions.ts`・`lib/fx.ts`・
  `lib/project-actions.ts`。同じ処理を 2 か所に書かない）。初めての保存は、保存先を選ぶ窓が開き、選ぶのは利用者
- **クリップを縮める・分ける・フェードは、タイムラインと同じ処理を呼ぶ**（計算は `lib/clip.ts`。端のドラッグ・メニュー・
  フェードの窓・ツールが、どれも `TimelineEngine` の `trimClip` / `splitClipAt` / `setClipFades` を通って、元に戻す履歴に載る）。
  位置は秒か小節で受ける（`trim_clip` は、端の新しい位置。`end_bar` は、その小節の終わりまで）。`split_clip` は、位置を省くと
  再生位置で分ける（画面の「再生位置で分割」と同じ）。音声は書き換えないので、縮めたぶんは、端を戻せば戻る。そのために、
  `get_project` は、縮めてあるクリップに、音声の中の位置（`audio_start_seconds`）と音声の全体の長さ（`audio_duration_seconds`）を
  添える。端は、音声の端より外へは伸びない（頼まれた位置で止まらなかったときは、結果に書いて返す。失敗にはしない。
  「元の長さに戻して」を、大きめの値でも通せるように）。音声の無い範囲だけを指したとき・フェードの合計がクリップの長さを
  超えるときは、失敗として理由を返す（黙って丸めると、言ったとおりになっていないのに「できた」と答えてしまう）

### ツールの結果

成功は JSON の文字列 `{"ok": true, "summary": "<日本語の 1 行>", …データ}`。`summary` は、操作ログの行にそのまま出す。
失敗は `is_error: true` で、`content` は理由の文（日本語。何を直せば通るかが分かるように）。

**失敗の文は 2 つ持つ**（`ToolError` の `message` と `shown`）:

- Claude に返す文（`message`）: 何を直せば通るかを、ツールや引数の名前を使って書く
  （「track_id 99 のトラックはありません。get_project で id を確かめてください」）
- 操作ログと動きの記録に出す文（`shown`）: 利用者向け。ツールや引数の名前と、「利用者に〜してもらってください」の
  ような Claude への頼みを入れない（「そのトラックが見つかりませんでした」）
- 引数の指定が合わなかった失敗（名前・型・範囲・組み合わせ。`ArgError`）は、Claude の呼び方の問題なので、
  操作ログには決まった文「指定が合わず、行っていません」だけを出す（Claude は、直して呼び直すことが多い）
- 成功の `summary` と失敗の `shown` に、内部の名前が入っていないことは、ツールの単体テストの `ok` / `fail` が、
  通るたびに確かめる（下線でつないだ名前、「利用者」、`true` / `false`）

### 場所を示す

示せる場所の一覧は `web-ui/src/lib/assistant-landmarks.ts`（名前・画面での名前・どこに在るかの文・セレクタ・開くタブ）。
台帳の `show_in_app` の `target` の選択肢と同じ名前で、過不足は単体テストが止める。示すときは、その場所の在る
タブを開き（`setLeftTab` / `openLearn` / `setSoundTab`）、部品に `assistant-pointer` のクラスを 4 秒付ける
（縁が光る。動きを減らす設定では光るだけ）。出ていない場所（練習画面のあいだだけ出るもの、など）は、
出る条件の文を返す。アシスタントは、ボタンを代わりに押さない。

アプリのどこに何が在るかは、指示文にも短く書いてある（「Where things are in bunri」）。指示文は変わらないので、
プロンプトキャッシュに載る。

## 元に戻す

1 回の依頼（利用者の 1 つの文から、アシスタントが答え終わるまで）で変えたことを、1 つの記録にまとめる。
依頼の中で最初に「変える」ツールを実行する前に `beginEdit` で記録を開き、依頼が終わったとき
（答え終わった・中止した・失敗した）に閉じる。中の `record` は、外側の記録にまとまる（store の既存の仕組み）。

- 記録の名前は「アシスタント: <依頼の頭 20 文字>」
- 何も変わらなかった依頼（読むだけ、再生だけ）は、記録を作らない
- 記録が開いているあいだ（アシスタントが動いているあいだ）は、利用者の「元に戻す」は効かない（store の既存の決まり）

## 操作ログ

- ツールの呼び出し 1 つが 1 行。成功は `summary`、失敗は理由。実行中は「〜しています…」
- 行を開くと、その操作のあいだに動きの記録（`lib/activity.ts`）に増えた行が出る（押されたものは無いが、
  ステータスバーの文・API の呼び出し・MIDI の行が入る）。「何をして、何が起きたか」を 1 か所で読める
- 同じ内容を、動きの記録にも札 `agent`（画面での呼び名は「アシスタント」）で残す。ファイルにも残る
- 会話と操作ログは、プロジェクトにも入る（次の節）。行を開いて出る動きの記録の行は入れない

## 会話の保存と、長くなったときのまとめ

Claude に送る会話（Messages API の形）と、画面に並ぶもの（文・操作ログの行・知らせ）は、別に持つ
（`lib/assistant.ts` の `messages` と `items`）。保存とまとめは、画面に並ぶものを材料にする（`lib/assistant-history.ts`）。

**保存**（`lib/assistant-project.ts`。プロジェクトの状態の節 `assistant`）:

- 入れるのは、画面に並ぶもの（利用者の文・アシスタントの文・操作ログの行・知らせ・依頼の終わりの行）。
  新しいほうから 300 個、文 1 つは 4,000 文字まで。**Claude に送る会話は入れない**（思考のブロックは、作った
  会話の中でしか通らない。トラックの ID も、開き直すたびに変わる）
- 開くと、並びが戻り、その後ろに「ここまでは、プロジェクトに保存してあった会話です」の区切りが出る。
  「元に戻す」は出さない（開き直したら、元に戻す履歴は無い）
- 会話は、プロジェクトごと。新しいプロジェクトにする・会話の入っていないプロジェクトを開くと、空になる。
  履歴から消した会話は、次の保存でプロジェクトからも消える
- 依頼の途中でプロジェクトを開いた・新しくしたときは、その依頼を中止し、終わったところで、開いたプロジェクトの
  会話に置き換える（前のプロジェクトの会話を残すと、次の保存で別のプロジェクトのファイルに入る）。その依頼の、
  元に戻す履歴の記録は作らずに閉じる（前と後で、別のプロジェクトになるため。`commit({ discard: true })`）
- **履歴**（2026-11-19 の利用者の依頼。節の版 2）: 「新しい会話」を押すと、それまでの会話（画面に並んでいたもの）を
  消さずに履歴の頭へ移す（空の会話は移さない）。履歴は節の `archive` に新しい順で入る（1 つは `{title, archivedAt, items}`。
  名前は最初の依頼の頭 30 文字。`MAX_ARCHIVED` = 30 個まで、超えたら古いほうから消える）。版 1 の節（`items` だけ）もそのまま読める
- ヘッダの「履歴」で一覧を出し、「開く」で開き直す（いまの会話は、空でなければ履歴へ移る）。開き直した会話は、
  プロジェクトを開き直したときと同じく、Claude に送る会話を空にして、並びから作った「これまでの記録」で続ける。
  区切りは「ここまでは、履歴から開き直した会話です」。動いているあいだは開けない（消すことはできる）
- 会話が増えただけでは、保存していない変更の印を付けない（質問しただけで「保存しますか」と尋ねないため）。
  会話は、プロジェクトを保存したときのものが入る
- プロジェクトのファイルを人に渡すと、会話も渡る。ドックの「Claude に送るもの」の説明に書いてある

**まとめ**（費用のかからない、決まった規則の記録。Claude は呼ばない）:

- 送る会話が長くなったら（100 件、または JSON で 200,000 文字を超えたら）、**次の依頼の前に**、送る会話を丸ごと
  捨てて、「これまでの記録」1 つで始め直す。記録は、画面に並ぶものから作る: 利用者の文・アシスタントの文
  （600 文字まで）と、操作ログの行（成功と失敗）を古い順に並べ、8,000 文字に収まるぶんだけ（古いほうから省く）
- プロジェクトを開き直した後の最初の依頼も、同じ記録で始める（送る会話が空で、画面に前の会話が並んでいるとき）
- 記録は、最初の user のメッセージとして送る（`<earlier_conversation>` で囲む）。指示文に「これは利用者の依頼ではなく、
  アプリが書いた記録。ID や位置は古いかもしれないので、読み直すこと」と書いてある
- **依頼の途中では縮めない。途中のメッセージだけを抜くこともしない**（後ろの思考のブロックが通らなくなる）。
  丸ごと置き換えれば、思考のブロックは 1 つも残らないので、検査に掛からない
- まとめた直後の 1 回は、会話のぶんのプロンプトキャッシュが効かない（台帳と指示文のぶんは効く）
- 画面には、「会話が長くなったので、ここまでを短い記録にまとめて Claude に渡します」の知らせが 1 行入り、
  並んでいるものは、そのまま残る
- Anthropic 側の仕組み（サーバ側のコンパクション、コンテキストの編集）は使わない。会話を画面が持つ形と、
  費用を手元で数える形を変えずに済むことと、本物の Claude で確かめずに入れられないため

## 費用

- 1 回の依頼で、Claude を何回か呼ぶ（ツールを使うたびに 1 往復）。上限は 12 回（`MAX_STEPS`）
- 使用量は `results/guide/usage.jsonl` に、呼び出し 1 回 1 行で残す（`feature: "assistant"`、`turn`、`step`）
- **1 日の上限（回数）は、依頼の数で数える**（`step` が 0 の行だけ）。呼び出しの数で数えると、
  ツールを 5 回使う依頼 4 つで既定の 20 回に届いてしまう。費用の上限（`daily_limit_usd`）は全部の行を足す
- 上限に達していたら、依頼の最初の呼び出しで断る（途中の呼び出しでは断らない。変えかけで止まらないように）
- 上限に達しているあいだは、ドックの入力欄の上に、アシスタントの言い方の知らせを 1 つ出す（数字から画面が作る。
  処理を担当する部分の `today.blocked` は再現ガイドの言い方なので、そのままは出さない）。上限で断られた依頼の
  知らせが会話の最後に出ているあいだは、入力欄の上の知らせは出さない（同じことを 2 か所に出さない）
- プロンプトキャッシュ: ツールの台帳と指示文は変わらないので、指示文の末尾に区切りを置く。
  会話は足すだけなので、リクエスト全体の自動の区切り（top-level の `cache_control`）で、前の往復までが効く。
  **指示文に、時刻・乱数・プロジェクトの中身を入れない**（プロジェクトの様子は `get_project` で読ませる）
- モデルは再現ガイドと同じ設定（`llm_settings.model()`。既定 `claude-opus-5-5`）。思考の深さは `medium`
- 本物の Claude での確認（ツールの定義が通るか、キャッシュが効くか）は、費用がかかるので、利用者の了承を取ってから行う
- 2026-11-18 に本物の Claude（`claude-opus-5-5`）で確かめた: 39 個のツール定義と指示文が通る、少しずつ返す形で文の差分と
  最後の行が届く、台帳と指示文（約 12,500 トークン）が 2 回目以降の呼び出しでキャッシュから読まれる、`add_notes` の引数が
  台帳どおりに来る。読むだけの依頼（2 回の呼び出し）で概算 $0.013、ノートを置く依頼（2 回）で $0.012。
  このとき、返事に Markdown の記号（`**`）が入ることが分かったので、指示文に「返事は、そのままの文字で出る。Markdown を
  使わない」を足した（ドックは、返事を文字のまま出す）

## テスト

- Python: 偽のクライアント（`tool_use` を返すもの）で、リクエストの組み立て・応答の写し方・上限・失敗の変換
- 画面: ツールの実行（引数の確かめ、元に戻す）、繰り返し、操作ログ、台帳との名前の一致
- e2e: 偽の Claude サーバ（`web-ui/e2e/fake-anthropic.mjs`）がツールを呼ぶ応答を返す。本物は呼ばない

## 倣ったこと・変えたこと（pairbrush）

| | pairbrush | bunri |
|---|---|---|
| ツールの実行 | アプリ側 | 同じ |
| 繰り返し | アプリ側が回す。サーバは状態を持たない | 同じ |
| モデルへの渡し方 | 構造化出力（操作の計画を JSON で 1 つ返す） | Claude のツール呼び出し（`tool_use`）。操作を 1 つずつ行い、結果を見て次を決められる |
| 元に戻す | 1 つの計画が 1 手 | 1 回の依頼が 1 手 |
| 確認 | ゴーストで見せて受け入れる | 確認なしで行い、1 回で戻せる（bunri の決まり） |
| 操作ログ | 1 リクエスト 1 件。画像は残さない。失敗・中止も残す | ツール 1 つ 1 行。文字だけ。失敗・中止も残す |
| 台帳 | 1 か所から生成し、検査する | 1 か所（JSON）を Python が読み、画面は名前の一致をテストで確かめる |

## やっていないこと

- 曲の取り込み（ファイルを選ぶ窓は、アシスタントからは開けない。場所を示す）
- 再現ガイドと差分の説明を、アシスタントから作ること（Claude をもう 1 回呼ぶ。保存済みのガイドは読める）
- 時間のかかる処理が終わったときに、アシスタントから知らせること（終わったかは、利用者が聞いたときに `get_job` で読む）
- トラックの音色（そもそもトラックの属性として無い）、シンセとドラムのパターンを音声にすること（「音作り」のパネルで）
- クリップの音量そのもの（クリップごとのゲイン）、フェードの曲線の形（直線だけ）、隣のクリップとのクロスフェード
  （アプリの側に、その仕組みが無い。音量はトラックの音量で変える）
- 会話を、Claude に要約させてまとめること（まとめは、決まった規則の記録）
- 操作ごとの ON / OFF の設定
- 本物の MIDI 鍵盤での確認、初めての保存で保存先の窓が開くところの確認（テスト用のビルドは窓を出さない）
