# 差分コーチ（第3層）— ノートの差分と、その言語化

第3層は「利用者の打ち込みと原曲の差分を指摘する」層で、製品の差別化の本命
（[song-chart-design.md](song-chart-design.md)）。実装したのは 2 つ。

1. **事実を出す部分**（ノートの差分）。LLM は使っていない。画面まで出来ている
2. **言葉にする部分**（どんな傾向の違いか、なぜ起きたと考えられるか、まず何を見直すか）。Claude を使う。
   **バックエンドだけ**出来ていて、画面はまだ無い。下の「言語化（差分の説明）」

> **暫定の実装。** 第3層の設計はまだ詰めていない（学習履歴の置き場、お手本の見せ方など）。
> 「いま実装できるものを進めてよい」との指示で、設計の決定を待たずに作れる部分を先に作った。
> 言語化の決定も、実装者の判断で埋めたもの。本物の Claude では、まだ 1 回も確かめていない。

## 何が出来るか

お手本（原曲を採譜した時点のノート）と、いまの打ち込みを突き合わせ、次を返す。

- お手本のうち、高さと位置が合っていた割合
- 指摘の一覧。種類は 6 つ: 抜け / 高さの違い / オクターブ違い / 余分なノート / 位置のずれ / 長さの違い
  （画面での呼び名。ことばの決まりは [ui-terms.md](ui-terms.md)）
- 指摘が重い小節（まず見るとよい場所）

画面では左パネルの「学ぶ」タブの「差分」の段に「差分チェック」として出る。指摘は
「2 小節 3 拍目: E4 が抜けています」のように、決まった型の文にする（これも LLM ではない）。

## 決めたこと

| 項目 | 決定 | 理由 |
|---|---|---|
| お手本 | パート分離（採譜）で作ったパートのトラックが、採譜したノートを `referenceNotes` として持つ。打ち込み（`pianoNotes`）は**空のまま**渡す（2026-11 に変更。それまでは同じノートを打ち込みにも入れていて、差分が最初から 100% だった） | 比べる相手が最初から答えそのものだと、差分コーチが成り立たない（[song-chart-design.md](song-chart-design.md) の「ゴースト表示」）。採譜を自由に直したい人には「お手本をノートとして取り込む」を残す（確かめてから写す） |
| 比べる相手 | お手本を持つトラック自身、または別のトラック | 採譜を直した結果の確認にも、自分で一から打ち込んだものの確認にも使えるように |
| 突き合わせ | 同じ高さ → オクターブ違い → 2 半音以内の違い、の順に、位置の近いものから組にする | 軽い違い（位置・長さ）を、重い違い（抜け・余分）として数えないため |
| 位置の許容 | 16 分音符 2 個まで | 人が打ち込むときの小さなずれを「別の音」にしないため。暫定の値 |
| 正確さ | 高さと位置（許容内）が合っていたお手本の割合。長さの違いと小さな位置のずれは、合っている側に数える | まず「音が合っているか」を見せるため |

## 限界

- **お手本そのものが間違っていることがある。** お手本は自動採譜の結果で、原曲の正解ではない。
  採譜の誤りは、そのまま「抜け」「余分」として出る。画面では「お手本」と呼び、「正解」とは言っていない
- ドラムは対象にしていない（ドラムは種類ごとに決まった高さへ置いた近似のため）
- テンポ揺れは見ていない。お手本も打ち込みも、同じグリッド（16 分音符のステップ）に載っている前提。
  グリッドはカルテの平均のテンポの等間隔なので、テンポが揺れる曲では、曲の後ろほどカルテの実測の拍からずれる

## お手本を見ながら打ち込む

お手本と打ち込みを、ピアノロールの上でつなげてある。

- **このパートを練習する**: パートの一覧（「学ぶ」の「曲とパート」）か、パートのトラックの見出しの「練習する」で、
  練習のトラック（「ベースの練習」。`role: 'practice'`、`practiceOf` がパートのトラック）を作るか選び、
  ピアノロールで開いてそのパートのお手本を重ね、お手本の在る高さと最初の小節までスクロールし、
  差分チェックの組を「お手本 = パート、打ち込み = 練習のトラック」にし、パートの音声を鳴るようにする。
  練習のトラックをパートのトラックと分けたのは、パートの音声と自分の打ち込みを別々にミュートできるようにするため（暫定）
- **お手本の重ね表示**: ピアノロールの見出しの「お手本を重ねる」で、お手本のノートを薄く重ねる。
  既定では、開いているトラックがお手本を持っていればそれを、練習のトラックならそのパートのお手本を重ねる。
  自分で一から打ち込むトラックでは、お手本にするトラックを選ぶ。お手本は見るだけで、押しても反応しない
  （下のグリッドに届くので、お手本をなぞってダブルクリックすれば自分のノートが入る）
- **指摘から移動**: 差分チェックの指摘を押すと、比べた打ち込みのトラックがピアノロールに開き、
  再生位置がその拍へ移り、タイムラインとピアノロールがその小節まで横に、ピアノロールはその音の高さまで縦にも動く

## カルテとピアノロールの小節番号（2026-11 に直した）

**直す前の不具合。** カルテは実測のビートと 1 拍目の位置（`grid.downbeat_offset_sec`）で小節を数える
（[grid-estimation.md](grid-estimation.md)）。ピアノロール・タイムライン・再生は 0 秒から整数の BPM で数え、
採譜（`decompose.py`）も 0 秒から、カルテとは別に推定した整数の BPM で数えていた。1 拍目が 0.75 秒に在る曲では、
「カルテの 3 小節」（4.75 秒）はピアノロールでは 3 小節目の頭から 3/8 小節ずれた場所だった。
カルテのコードを見ながら打ち込むと、番号どおりの場所に置いても音がずれる。

**決めたこと（暫定）。** プロジェクトのグリッドを、カルテのグリッドに合わせる。

| 項目 | 決定 | 理由 |
|---|---|---|
| グリッドの持ち方 | テンポ（小数 2 桁）・拍子・1 小節目の位置（`gridOffset` 秒）の 3 つ。ピアノロールのステップ 0 は `gridOffset`。再生・書き出し・メトロノーム・タイムラインの小節番号・MIDI 入力の録音位置も、ここから数える（`web-ui/src/lib/grid.ts`） | 番号の付け方を 1 か所にまとめると、カルテ・ピアノロール・タイムライン・差分チェックの番号が同じになる |
| 曲を取り込んだとき | カルテのテンポ・拍子・1 拍目の位置を、そのままプロジェクトのグリッドにする | 3 つの案（下）のうち、画面に出る番号がどこでも一致するのはこれだけ |
| 採譜 | パート分離に、プロジェクトのテンポと `grid_offset` を渡す。採譜はステップを `grid_offset` から数える（`decompose.seconds_to_step`） | お手本がピアノロールのグリッドにそのまま載る。秒から数え直す（二重に丸める）とステップが 1 つずれることがある |
| 1 小節目より前（弱起） | 採譜した音のうち、1 小節目より前に始まるものは置かない。タイムラインには、その区間の拍の目盛りを番号なしで描く | ピアノロールは負のステップを持てない。カルテも 1 小節目より前を数えていない。グリッド推定は 1 拍目を曲頭から 1 小節未満の位置に置くので、落ちるのは最大でも 1 小節ぶん |
| テンポの精度 | 小数 2 桁（以前は整数に丸めていた） | 128.3 を 128 に丸めると、3 分の曲の終わりで 0.4 秒（16 分音符 3 つぶん）ずれる |
| パートに分けた後でグリッドを直したとき | プロジェクトのグリッドは変えない（お手本は直す前のグリッドで採譜してある）。直した旨と「もう一度パートに分けると合う」をステータスバーに出す。分け直すときは、カルテのグリッドを当ててから採譜する | グリッドだけ変えると、お手本と打ち込みが原曲の音からずれる。番号がずれても、カルテやガイドからの移動は秒で行うので、場所はずれない |
| カルテ・ガイドからの移動 | 小節番号ではなく、カルテの実測のビート列から引いた秒で移る（`chartBarToSec`） | テンポが揺れる曲や、上の「直したとき」でも、カルテが指す音の場所へ行ける |
| 保存したプロジェクト | `gridOffset` を保存する。以前の版のプロジェクト（`gridOffset` が無い）は 0 として読む | 以前のノートは 0 秒から数えて置いたものなので、0 で読めば同じ場所に鳴る |
| 言語化（`coach_explain`） | `grid_offset_sec`（ステップ 0 の位置）を受け取り、ステップを秒に直すときに足す。無ければ 0（以前と同じ） | 引き続き秒で突き合わせる（テンポ揺れ・グリッドを直した場合に強い）。画面の差分チェックの小節番号は、ピアノロールと同じステップから数えるので一致する |

**ほかの案と、選ばなかった理由。**

- **秒で変換するだけ**（カルテ↔ピアノロールの境目ごとに秒を通す）: 移動は正しくなるが、画面に出る番号は
  カルテとピアノロールで違ったまま。「5 小節目のコードは G」と読んで、ピアノロールの 5 小節目に置くと間違う
- **採譜だけカルテのグリッドに合わせる**: ピアノロールの再生と目盛りが 0 秒からのままなので、お手本が原曲とずれて鳴る

**確かめているテスト。** `test/back/test_decompose.py` の `TestChartAndPianoRollBars`（1 拍目が 0.75 秒の合成音で、
グリッド推定 → カルテの 3 小節目の頭で鳴る音を採譜 → ピアノロールの 3 小節目の頭（ステップ 32）に置かれる。
0 秒から数えると置かれない）、`web-ui/src/__tests__/grid.test.ts`（カルテの N 小節とピアノロールの N 小節の時刻が一致する）、
`web-ui/e2e/learn.spec.ts`（1 拍目が 0.75 秒のカルテで、タイムラインの 1 小節目の線が 0.75 秒の位置に在り、
コードの 3 小節目を押すとピアノロールの再生位置の線がステップ 32 に来る）。

## 言語化（差分の説明）

差分の一覧は「どこが違うか」までしか言わない。そこから「どんな傾向の違いか、音楽的になぜ
そうなったと考えられるか、まず何を見直すか」を言葉にする。第2層（再現ガイド）と同じ仕組みで、
同じ保証を付けてある（[reproduction-guide-design.md](reproduction-guide-design.md)）。

### 原則の守り方

**DSP が事実を出し、LLM は言語化だけをする。LLM は音符を 1 つも出力しない。**

| 仕組み | 何を防ぐか |
|---|---|
| 差分は、画面が送ってきた結果を使わず、ノートからサーバの側で計算し直す | 事実でないものを「事実」として LLM に渡すこと |
| 数えれば決まることは、コードが計算して渡す（遅れと早まりの数、拍の頭か裏か、半音の差、その音がコードの何度か、キーの音階に在るか） | LLM の数え間違い・度数の言い間違い（第2層で、機械的な計算を LLM にさせると間違えた） |
| 出力の形を Structured Outputs で固定する。持てるのは説明文と、指摘の ID・小節番号だけ | 音符のデータを返すこと。形の上で入れる場所が無い |
| 指摘の ID・小節への参照を事実と突き合わせ、実在しないものは落とす | 存在しない場所へのリンク |
| 説明文のオクターブつきの音名（E2 など）を事実と突き合わせ、事実に無い音を書いた点は点ごと落とす。全体の要約と「最初にやること」に書かれていたら、その欄を決まった文に差し替える | 新しい音の提案（「ここに A2 を入れる」）。お手本にも打ち込みにも無い音は、画面に出ない |
| 参照が 1 つも残らない点は落とす。点が 1 つも残らなければ失敗にする | 差分の結果と結び付かない一般論 |
| そのほかの音名・コード名・小節番号で事実に無いものを「未確認の語」として返す | 事実に無いコードや場所を説明文に紛れ込ませること（第2層と同じ見張り。遮断ではない） |

第2層より 1 段きびしいのは、オクターブつきの音名だけ。「E2」のような書き方は、ほかの意味に読める
場面がほとんど無い（第2層で遮断にしなかった理由は「A メロ」のような誤検出）。高さで比べるので、
同じ音の別の書き方（A#2 と B♭2）は同じに扱う。コード名の「G7」は「G のオクターブ 7」と同じ形になるので、
事実に在るコード名と一致するものは音名として数えない。

### LLM に渡す事実

`coach_explain.build_facts` が組み立てる。音声もファイル名も渡さない。

| 項目 | 中身 |
|---|---|
| `summary` | 全体の件数（`coach_diff` と同じ）。割合は百分率に直してある |
| `tendencies` | 種類ごとの偏り。位置のずれは遅れ・早まりの数と平均、長さは長い・短いの数、高さの違いは高い・低いの数と半音ごとの数、抜けと余分なノートは拍の頭・裏の数と拍ごとの数。**全部の指摘から数える** |
| `bars` | 小節ごとの種類別の件数（60 行まで。超えるときは、重い小節と件数の多い小節を残す） |
| `issues` | 指摘の表（**40 件まで**）。ID、小節、拍、種類、お手本の音、打ち込みの音、半音の差、位置のずれ、長さの違い。`total` が全件の数 |
| `worst_bars` | 指摘が重い順の小節（`coach_diff` と同じ） |
| `key` `sections`、`issues` の `chord` `expected_role` `actual_role` | カルテが在るときだけ（下の「カルテとの突き合わせ」） |

- **指摘の ID** は、`coach_diff.diff_notes` の `bars[].issues[]` を上から数えた番号（`i1` `i2` …）。
  `POST /api/coach/diff` の結果を同じ順に数えれば、画面の側でも同じ ID になる
- **指摘が 40 件を超えるとき**は、一部だけを渡し、全体は `summary` `tendencies` `bars` で伝える。
  選び方は、画面の一覧と同じ並び（重い小節が先、あとは小節順）で、種類ごとに枠を分けて取り、余った枠を
  上から埋める。そのまま上から取ると、1 種類だけで埋まることが在るため（ある区間を丸ごと打ち込んで
  いないと、抜けだけで 40 件になる）
- 同じノートからは、いつも同じ事実（同じバイト列）になる。これを保存の鍵に使う

### カルテとの突き合わせ

リクエストに `chart_id` を付けるとキーを、さらに `bpm`（お手本を採譜したときのテンポ）も付けると、
その場のコードとセクションを事実に足す。

- **カルテの小節番号は使わない。** 画面はふつうカルテのテンポと 1 拍目の位置をピアノロールに使うので番号はそろうが
  （上の「カルテとピアノロールの小節番号」）、テンポが揺れる曲や、パートに分けた後でグリッドを直した場合はずれる。
  そこで、ピアノロールのステップを秒に直し（`grid_offset_sec` + ステップ × 1 ステップの秒）、カルテのコード・
  セクションの秒の範囲と突き合わせる。`grid_offset_sec` が無いときは 0（以前の、0 秒から数えるピアノロール）。
  LLM に渡す小節番号は、すべてピアノロールの番号（画面が移動に使う番号）
- `bpm` が無ければ秒に直せないので、キーだけを使う
- コードは、ステップの真ん中の時刻で引く。採譜はノートの頭をステップに丸めているので、コードの
  変わり目に在る音が、丸めで手前のコードに入るのを避けるため
- 音ごとに、その場のコードの何の音か（ルート・3度・5度・7度）、コードの音でなければキーの音階に
  在るか（コード外・キー内 / コード外・キー外）を計算して渡す。キーの音階は、メジャーと自然的短音階
- 確信度は、第2層と同じ 3 段階（確実 / たぶん / 自信なし）に直して渡す

### 出力の形と、API が返す形

LLM の出力（`COACH_SCHEMA`）は `summary`、`points[]`（`title` `observation` `cause` `fix` `issue_ids[]`
`bars[]`）、`next_step`、`next_step_bar`。検証のあと、API は次の形で返す。

- `summary`: 全体の傾向（2〜3 文）
- `points[]`: 見直すとよい点。1〜3 個、直す効果が大きい順。`title` / `observation`（どんな傾向か）/
  `cause`（なぜと考えられるか。推測なので断定させない）/ `fix`（どこを何と見比べるか）/
  `refs[]`（`{issue_id, bar, beat, kind}`。指摘を指すものが先、あとに小節だけを指すもの。
  小節と拍はサーバが引いて付けるので、画面はそのまま移動に使える）
- `next_step` と `next_step_bar`: 最初にやること 1 つと、その小節
- `dropped_refs` `dropped_points`（落とした参照・点の数）、`unverified_terms`（未確認の語）、
  `replaced`（決まった文に差し替えた欄の名前）

言い方の約束（指示文に書いてある）: 「お手本」と呼び、「正解」「答え」とは書かない。打ち込みを
「間違い」と決めつけず「お手本と違っています」と書く。お手本は自動採譜の結果で原曲どおりとは
限らないので、お手本の音のほうが不自然に見えるときは、採譜の誤りかもしれないと添える。
励ましやほめ言葉は書かない。

### Claude を呼ばない場合

傾向と言えるものが無く、呼んでも一覧を言い直すだけになるときは、決まった文を返す
（`rule_response`。応答の `source` が `"rule"`、費用は 0、記録もしない）。

| `reason` | 条件 |
|---|---|
| `no_diff` | 違いが無い |
| `no_attempt` | 打ち込みのノートが 1 つも無い |
| `few_notes` | お手本が 4 ノートより少ない |
| `few_issues` | 違いが 3 か所より少ない |

### 費用

第2層と同じ仕組みを、同じ部品で使う（[reproduction-guide-design.md](reproduction-guide-design.md) の「費用」）。

| 仕組み | 第3層での中身 |
|---|---|
| 説明の保存 | 鍵は、事実の指紋 + モデル + 思考の深さ + 指示文と出力の形の指紋。同じノート・同じ条件なら Claude を呼ばない。置き場は `results/coach/cache/`（`guide_cache` の `kind="coach"`） |
| 同時に走らせない | 説明の呼び出しを 1 つずつ通す（連打・二重送信で 2 回呼ばない） |
| 1 日の上限 | **再現ガイドと同じ 1 つの枠**（既定 20 回）。再現ガイドと説明を合わせて数える |
| 使用量の記録 | 再現ガイドと同じ `results/guide/usage.jsonl`。どちらの呼び出しかは `feature`（`guide` / `coach`）で見分ける。ノートも説明文も残さない |
| モデルと思考の深さ | 第2層と同じモデル（`llm_settings.model()`）、思考の深さは `low` |
| 入力を絞る | 指摘は 40 件まで、小節の表は 60 行まで。上限まで渡しても、指示文・事実・出力の形を合わせて 7,000 文字ほど（カルテ無しのとき） |
| 入力の量の確認 | 設定の `max_input_tokens` を超えるときは、呼ばずに知らせる（上の上限が在るので、設定を下げない限り当たらない） |
| プロンプトキャッシュ | 指示文の後ろに区切りを打つ。事実は毎回変わるので、効くのは「直して比べ直す」を 5 分以内に続けたときの、指示文と出力の形のぶんだけ |

### API

`POST /api/coach/explain` と `POST /api/coach/explain/saved`（Claude を呼ばずに返せるものだけを返す。
画面が、お手本と比べた直後に呼ぶ想定）。本文は JSON で、`reference` `attempt`（必須）、`steps_per_bar`
`steps_per_beat` `timing_tolerance`（`/api/coach/diff` と同じ）、`chart_id` `bpm`、`regenerate`。
失敗の返し方（ステータスと `detail` の `{message, code}`）は、再現ガイドと同じ。

### 決めたこと（どれも暫定）

| 項目 | 決定 | 理由 |
|---|---|---|
| 入力 | ノートを受け取り、差分をサーバで計算し直す | 画面が送る「差分」を信じると、事実でないものが LLM に渡りうる |
| 渡す指摘の上限 | 40 件 | 画面の一覧の上限と同じ。傾向は件数の集計で伝わるので、1 件ずつは例として足りる数でよい |
| 点の数 | 1〜3 個 | 細いパネルで読みながら手を動かす。多いと「まず何を」がぼやける |
| 事実に無い音 | 点ごと落とす（要約と「最初にやること」は差し替える） | 「LLM は音符を出さない」を、説明文の中でも守るため。応答ごと捨てると、費用だけかかって何も出ない |
| 参照の無い点 | 落とす | 画面は、点から小節へ移動できる前提で出す |
| 違いが 3 か所より少ないとき | Claude を呼ばない | 傾向とは言えず、一覧を読めば足りる |
| 上限と記録 | 再現ガイドと共通 | 利用者から見れば、どちらも同じ「Claude の費用」 |
| 思考の深さ | `low` | 第2層に合わせた。第2層は実測で決めたが、こちらは**測っていない** |
| カルテ | 任意。小節番号ではなく秒で当てる | カルテとピアノロールのグリッドが別物のため |
| 種類の呼び名 | 画面の一覧と同じ「高さの違い」「余分なノート」 | お手本は正解ではないので、「間違い」と言わない。呼び名は [ui-terms.md](ui-terms.md) に合わせる（当初は「音の違い」「余分な音」だったが、画面の見直しで一覧と合わせた） |

### 確かめられていないこと

- **本物の Claude での出来。** 偽のクライアントでしか動かしていない。出力の形が API に受け付けられるか、
  指示文で狙った書き方（傾向をまとめる、断定しない、音を提案しない）になるか、落とす点がどのくらい出るか、
  1 回あたりの費用、プロンプトキャッシュが効くか（区切りまでが、キャッシュできる最小の長さを超えるか）は未確認。
  `scripts/guide_probe.py` に、説明を試すコマンドはまだ無い
- 思考の深さ `low` で足りるか
- 「原因」の質。事実に手がかりが無いときに、もっともらしい理由を作らないか
- カルテとの突き合わせは、お手本を採譜したあとでテンポを変えていない前提。変えていると、秒がずれる
  （サーバからは見分けられない）。お手本のトラックと同じ曲のカルテかどうかも、画面が判断して送る
