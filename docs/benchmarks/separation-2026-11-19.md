# 分離モデル比較の結果（2026-11-19）

モデルを最新にすれば全部が改善する、という結果ではなかった。次の導入候補は、精度優先で
**SubRoformer＋MPS**、CPUでの速さ優先で **SCNet小型＋ONNX** とする。
今回の作業は比較と選定まで。アプリの既定モデルは変更していない。

その後の本番実装で両モデルを画面へ追加し、SubRoformerを既定にした。
現在の使い方は [パート分離の品質と音量](../separation-quality.md) を参照。

## 条件

Apple M5、メモリ24 GiB、macOS 26.5.2。現行FTと6s、新モデル2つ、小型ONNXの計5モデルを
7つの実行条件で比較した。ゲーム音楽の15秒区間2つと、SigSep公式test先頭3曲の各6.8秒、
合計50.4秒。7条件×5区間の **35/35処理が成功**。

正解付き3曲はAAC圧縮サンプルで、参照4パートの和を入力にした。2曲目には参照側の既知の問題がある。
各方式をケースごとに順番に一回ずつ、入力と出力の音量を合わせずに実行した。
指標・入力の選び方・再現方法は [比較方法](separation-method.md)。

## 集計

精度・音量差は正解3曲×4パートの単純平均。**波形SDRは大きいほど誤差が少ない**。
論文のBSS EvalのSDRとは異なり、論文の数値と直接順位を付けない。
時間は全5区間のプロセス起動・読込・推論・保存の合計（モデル読込5回）。
RSSは各ケースの最大値の中央値で、GPU/ANE/別サービスを含む総メモリでも、
Python＋Nodeの同時合計でもない。

| モデル・基盤 | 平均波形SDR dB ↑ | 平均絶対音量差 dB ↓ | 合計秒 ↓ | 最大RSSの中央値 MiB |
|---|---:|---:|---:|---:|
| Demucs FT / CPU | 7.82 | 0.89 | 134.4 | 2278 |
| Demucs 6s / CPU | 7.46 | 1.75 | 36.9 | 1749 |
| SubRoformer / CPU FP32 | 9.72 | 0.96 | 494.8 | 1990 |
| SubRoformer / MPS FP16 | 9.72 | 0.96 | 186.5 | 878 |
| SubRoformer / Core ML FP16 | 9.72 | 0.97 | 197.0 | 1642 |
| BS-RoFormer-SW / MLX | 9.65 | 1.33 | 55.5 | 1537 |
| SCNet小型 int8 / JavaScript＋ONNX CPU | 8.16 | 0.92 | 36.3 | 1785 |

SCNetは小型の量子化版。SCNet XLや浮動小数点の原版の結果ではない。
BS-RoFormer-SWは6パートを4パートへまとめた。重みの許諾がunknownのため実験のみで、配布対象にはしない。
CPU/MPS/Core MLでは数値精度・演算器・前後処理の条件が異なるので、言語だけの比較ではない。

## 導入判断

- **精度優先の次候補はSubRoformer＋MPS**。今回のFT比で平均波形SDRが約1.90 dB高く、
  4カテゴリの平均も改善。ただし音量差は0.89→0.96 dBと改善していない。
  MPSは同じモデルのCPU版より約2.7倍速かったが、現行FTのCPU版よりは遅い。
  Core MLとの精度差は小さい。単発の速度差で優劣を確定せず、既存Torchと統合しやすいMPSを先に検討する。
- **CPUでの速さ優先の次候補はSCNet＋ONNX**。全区間の総時間はFT比約3.7倍速く、
  平均波形SDRも約0.33 dB高かった。ただしベースの平均は8.76→8.01 dBへ低下し、
  2曲目の全パート平均もFTを下回った。一律の上位版ではない。
  Rustへ組み込む場合は、今回のJavaScript版と同じONNX・前後処理で音声が一致することを先に検証する。
  Rust/C++への移植や、その速度測定は今回行っていない。
- **RoFormerは許諾確認まで搭載候補から外す**。今回のMLX版は精度と速度の両立が良かったが、
  この取得物をそのままアプリへ配布する判断はしていない。

ユーザーのゲーム音楽には各パートの正解が無いため、混入・欠落の正確な量やモデル順位を数値から断定しない。
この曲の聴感は未判定。聴き比べ音声は、正規化せずローカルのレポートへ残した。
3曲の短区間だけでは、ゲーム音楽全般やどの曲にも最良という結論にはならない。
また、パートの和が原曲に近いことは、各楽器の正しさの証明には使っていない。

## ローカルの成果物

元音声や分離音声はコミット・外部送信しない。

- `results/separation-bench/2026-11-19/runs/report.html`：同じ音量倍率で再生できる聴き比べと指標。
- 同じ場所の `report.json` / `summary.json`：35比較の集計と明細。
- 各ケース・各方式の `benchmark.json` / `metadata.json` / `process.log`：時間・RSS・ハッシュ・実行条件。
- `results/separation-bench/2026-11-19/inputs/manifest.json`：切り出し位置、公開サンプルの選定、ハッシュ、来歴。
- `results/separation-bench/2026-11-19/evidence/`：マシン情報、依存freeze、Node lockfile、Demucsキャッシュ重みの識別。

取得した他のモデル重みとコードの固定版・ハッシュはrunnerの定数と各metadataに残した。
外部環境は `/tmp/bunri-model-bench/`、実音声と結果は上記の `results/` へ分離している。

比較ツール・入力作成・各runnerの単体テスト36件、backend/testのruff、独立レビューが通過。
