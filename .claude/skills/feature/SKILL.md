# bunri の機能実装

ユーザーが依頼した機能を、現在の Python / React / Tauri 構成に沿って実装する。
共通規約はリポジトリルートの `.claude/CLAUDE.md`。関係する設計文書を読む。

1. 現在の実装と `git status --short` を確認し、完了条件と変更範囲を決める。
   環境で調べられる事実は調べる。仕様の選択が結果を大きく変えるときだけユーザーに確認する。
2. 複数領域にまたがる場合、API / Tauri command の引数・戻り値・エラーを先に揃える。
3. 独立した作業を `.claude/agents/backend.md` / `frontend.md` / `desktop.md` の役割へ委譲する。
   Codex では同名のカスタムエージェント、または担当文書を渡した組み込みエージェントを使う。
   担当ファイルと契約を明記し、同じファイルの編集は重ねない。小さな変更は自分で進めてよい。
4. 親が差分を統合し、データ形式・接続先・認証・エラー表示の整合を確認する。
5. `make check-plan` → `make check`。ブランチ全体なら `node scripts/check.mjs --base main`。
   UI 変更は E2E まで実施。ネイティブ機能の変更は必要なデスクトップ動作も確かめる。
6. 大きな変更や契約変更は reviewer に独立した差分確認を依頼し、具体的な不具合を解消する。

最後に、実現した挙動、検証結果、残る制約を短く報告する。依頼されていない commit / push / 公開は行わない。
